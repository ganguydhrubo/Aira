## Entry

First work out whether the user wants to read, draft or send, and which app and which account to use. If the user names an app, use that app; if it will not open or is not signed in, tell the user plainly.

## Steps

1. **Read**: first look at the chat list or inbox, find the right conversation and open it to read the full text; scroll up for older messages when needed, and note the sender, time, group members and attachments. For unread items, go by the red dots and numbers in the list.
2. **Find the recipient**: find the recipient by saved name, display name, group name or email address; when there are contacts, groups or channels with the same name, open their profile to check. For email, use the real address from the contacts or earlier emails.
3. **Draft**: write it the way the user wants. If the user only wants a draft, give them the draft and stop there; if the user wants it sent, send it once written, without asking first.
4. **Send**: go into the correct conversation or compose screen, type the text, add attachments, and check the recipient and the full text once more before sending.
5. **Check**: after sending, find the message bubble in the conversation, or find the email in the "Sent" folder, and look for any failed-to-send mark.

## Common pitfalls

- Search results often show many items with the same name but different profile pictures and saved names; tapping the wrong one sends to the wrong person.
- An empty input box does not mean the message went out; on a poor network a message may stay at "sending" or show a red exclamation mark. If you cannot see the sent message, check its status in the conversation before deciding to resend, so it is not sent twice.
- With some keyboards or input settings, pressing Enter sends the message straight away; for multi-line text, use the new-line key or type it in parts.
- The preview in the chat list shows only the start, not the full text.

## How to verify it is done (evidence)

Reading: the points and times you give all come from the opened conversation or email body. Sending: the sent message can be seen in the conversation, or the email is in "Sent", with the right recipient and content.

## When to stop and hand over to the user

When a sign-in or a verification code is needed, or the recipient or content could be more than one thing and the user has to choose, hand over to the user.
